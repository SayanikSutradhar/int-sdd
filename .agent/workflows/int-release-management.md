# INT Release Management Workflow

## 1. Purpose

This workflow manages the release of completed and approved Specs.

It is responsible for:

- Release readiness validation
- Identifying Specs included in the release
- Verifying all included Specs are Ready for Release
- Preparing release notes from Spec Intent
- Updating Spec states to Released
- Updating `status.md`
- Creating the Git release tag

This workflow MUST NOT implement business functionality.

The INT SDD Blueprint V1.0 is the sole source of truth for release management, lifecycle states, artefact structure, and release rules.

If this workflow conflicts with the INT SDD Blueprint V1.0, the Blueprint takes precedence.

---

# 2. Release Flow

The release lifecycle is:

```text
status.md
      ↓
Identify release scope
      ↓
All included Specs = Ready for Release
      ↓
Release Readiness Validation
      ↓
Release
      ↓
Specs → Released (vX.Y.Z)
      ↓
Release Notes from Spec Intent
      ↓
status.md updated
      ↓
Git Tag
```

---

# 3. Release Readiness Validation

Before releasing, verify for each included Spec:

- Gate 2 Approved
- All tasks complete
- All tests GREEN
- No open Sev-1/Sev-2 blocking incidents
- Release file prepared

---

# 4. Release Artifacts

Create:

```text
.ai-context/releases/RELEASE-vX.Y.Z.md
```

Derived from `release.template.md`.

---

# 5. Status Synchronization

After release:

1. Update all released Spec statuses to `Released (vX.Y.Z)` in `.ai-context/specs/`.
2. Update `.ai-context/status.md`.
3. Append to `.ai-context/prompt_history.md`.
4. Create Git tag `vX.Y.Z`.

---

# 6. Final Validation

Verify:

1. All included specs are Gate 2 Approved.
2. Release file exists.
3. All spec statuses updated to Released.
4. `status.md` updated.
5. Git tag created.
6. No business implementation generated by this workflow.
